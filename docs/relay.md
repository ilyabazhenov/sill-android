# Relay: Mac вне дома без Tailscale

Дома телефон ходит к Sill напрямую. Вне дома прямого пути нет: Mac за NAT, белого IP часто нет, а Tailscale
нужно ставить на оба устройства. Relay решает это так же, как в Walkship: Mac сам держит исходящее соединение
с сервером, а телефон, не найдя Mac другими путями, идёт через этот сервер.

Отличия от Walkship:

- Sill на Mac стоит как есть и только слушает. Исходящее соединение держит отдельная программа `rmhelper`
  (launchd-агент), которая передаёт подключения телефона в remote door Sill на `127.0.0.1:7455`.
  Remote door пускает loopback (`OriginPolicy.remoteAdmits`), поэтому в Sill достаточно включить Remote Access.
- Через relay идёт не HTTP, а непрерывный поток Sill (TLS 1.3 с видео). Relay ничего не разбирает: это
  слепая труба для байтов, по TCP, на своём VPS. Шифрование уже есть: внутри трубы TLS Sill, где телефон и Mac
  проверяют ключи друг друга. Relay видит только адреса, время и объём.

```
телефон ──TCP──▶ VPS: rmrelay :7456 ◀──TCP── rmhelper на Mac ──TCP──▶ Sill remote door 127.0.0.1:7455
        └─────────────── TLS Sill (sill/1, оба ключа запинены) ───────────────────────────┘
```

## Безопасность

Граница доверия та же, что у Sill: сеанс получает только сопряжённый ключ устройства, а сопряжённое устройство
управляет Mac полностью (клавиатура и мышь, включая поля паролей). Relay добавляет путь к двери Sill из
интернета, поэтому helper стоит перед дверью и пропускает к ней не всё.

- **Ключ доступа.** В QR-коде helper'а есть случайный ключ (16 байт). Телефон без него получает отказ от
  helper'а, и до Sill дело не доходит. Иначе любой, кто узнал адрес relay и id Mac, достучался бы до двери Sill.
  Через неё он смог бы: прочитать отпечаток ключа Mac; сжечь окно сопряжения; запереть relay. Sill блокирует
  источник на 5 минут после 5 отказов за минуту, а для Sill все телефоны через relay — один адрес, 127.0.0.1
  (`Door.swift`, `countFailure`). `rmhelper new-access` меняет ключ, и старые QR перестают работать.
- **Только сеансы.** Helper читает ClientHello телефона и пропускает к Sill только ALPN ровно `sill/1`. Сопряжение
  (`sill-pair/1`) через relay закрыто: окно сопряжения на Mac открывает и remote door. Ввод кода не защищён
  PAKE, и подменивший relay мог бы подбирать код офлайн. Сопрягаться дома, по QR-коду Sill.
- **Не больше 2 рукопожатий к Sill одновременно** (столько Sill держит с одного адреса) и не больше 8 сеансов.
  Отпечаток ключа Sill helper читает один раз при установке и хранит в настройках: каждое чтение для Sill —
  отказ от 127.0.0.1.
- **Ссылку relay из другого приложения или со страницы** телефон применяет только после подтверждения.
- **Через relay** общий буфер обмена выключен, пока его не включат: копии с Mac иначе шли бы через интернет.
- **Блокировка приложения.** Телефон с экранной блокировкой просит отпечаток, лицо или PIN при открытии и после
  минуты в фоне.

Что остаётся:

- Relay — это доступ из интернета, хотя Sill его так не называет. Сеансы через relay Sill показывает как
  «by address» и даёт им домашнее качество. Выключатель «Allow connections from the internet» их не
  останавливает, выключает только Remote Access.
- Кто знает ключ доступа (то есть видел QR), может запереть relay на 5 минут мусорными рукопожатиями.
- Потерянный телефон: удалить его в Sill на Mac (это рвёт его сеансы) и выполнить `rmhelper new-access`.
- Соединение с relay — открытый TCP. Содержимое скрыто TLS Sill. Ключ доступа, id Mac, адреса и объём видны
  по пути и владельцу VPS.

## Протокол (`relay/wire`)

Каждое TCP-соединение к relay начинается с `RMR1` и байта роли.

**Mac, управляющее соединение (`M`).** Одно на Mac, держится всё время.

1. Mac → `pub` (32 байта, ключ Ed25519 helper'а).
2. Relay → `nonce` (32 случайных байта).
3. Mac → подпись Ed25519 над `"remote-mac relay v1 mac" ‖ nonce` (64 байта).
4. Relay → статус (1 байт): `0` — принят, `0x10` — подпись неверна.

Id Mac = первые 16 байт SHA-256(`pub`), в тексте 32 hex-символа. Без ключа выдать себя за Mac нельзя, а relay
ничего не хранит: id вычисляется из ключа. Новое соединение того же Mac заменяет старое.

Дальше кадры по 1 байту вида:

| Кадр | Направление | Значение |
|---|---|---|
| `O` + token (16) + ключ доступа (16) | relay → Mac | телефон ждёт: проверь ключ и открой соединение `D` с этим token |
| `F` + token (16) + статус (1) | Mac → relay | сеанса не будет; статус уходит телефону |
| `P` | любое | ping, ответ `p` |
| `p` | любое | pong |

Relay шлёт `P` раз в 25 с. Кто ничего не получал 70 с, считает соединение мёртвым. Helper переподключается
с паузой от 1 с до минуты.

**Mac, соединение данных (`D`).** Mac → token (16). Дальше relay склеивает это соединение с телефоном. Helper
читает из него ClientHello телефона, проверяет ALPN, и только потом открывает Sill и передаёт ClientHello туда.
Если ALPN не `sill/1`, helper отвечает TLS-алертом `no_application_protocol`. Если Sill недоступен —
`internal_error` (телефон показывает «helper couldn't reach Sill»).

**Телефон (`C`).** Телефон → id Mac (16) + ключ доступа (16). Relay → статус:

| Статус | Значение |
|---|---|
| `0` | Mac открыл свою сторону; дальше сырые байты Sill |
| `1` | Mac не подключён к relay (helper не запущен, Mac спит или без сети) |
| `2` | занято: у этого Mac уже 8 сеансов через relay |
| `3` | Mac не ответил за 10 с |
| `4` | helper не смог открыть Sill |
| `5` | неверный ключ доступа (старый QR-код) |

После `0` телефон начинает обычное TLS-рукопожатие Sill поверх того же сокета.

## Ограничения relay

- Все первые байты (роль, ключ, подпись, token, id) — с таймаутом 10 с.
- Не больше 8 сеансов на Mac (столько же remote-сеансов держит сам Sill), 2048 соединений всего.
- Новые соединения с одного IP: 120 в минуту с запасом 40.
- Склеенные соединения живут, пока жив хотя бы один конец; TCP keepalive включён.

## Как телефон узнаёт relay

`rmhelper link` печатает QR-код ссылки

```
remotemac://relay?r=<host:port>&i=<id Mac>&s=<ключ доступа>&k=<отпечаток ключа Sill>&n=<имя Mac>
```

Приложение находит сохранённый Mac с этим отпечатком и запоминает для него relay и ключ доступа. Поэтому
сначала Mac нужно сопрячь обычным способом (дома), потом отсканировать QR от helper.

## Выбор пути на телефоне

Relay — ещё один кандидат в гонке remote-адресов (`Controller.raceRemote`), последний по порядку. Сначала идёт
сработавший в прошлый раз путь, потом VPN, LAN, интернет-адреса Sill, адреса, введённые руками, и только потом
relay. Если в прошлый раз сработал relay (`lastWorked = "relay:<host:port>"`), он идёт первым.
